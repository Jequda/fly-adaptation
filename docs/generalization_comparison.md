# Шаг 5. Повторяемость навигации

Сильный результат одного мозга отвечает только на вопрос «возможно ли это?».
Теперь мы проверяем, часто ли эволюция находит решение из других случайных
популяций.

## 1. Быстрая проверка команды

```powershell
uv run python -m experiments.compare_generalization --generations 5 --population 16 --episodes 8 --validation-episodes 8 --holdout-episodes 16 --max-steps 80 --workers 4 --replicates 2 --open-viewer
```

Этот запуск нужен для знакомства с отчетом. Маленькая популяция и пять
поколений не являются проверкой гипотезы.

## 2. Полный протокол

```powershell
uv run python -m experiments.compare_generalization --generations 40 --population 80 --episodes 24 --validation-episodes 24 --holdout-episodes 64 --max-steps 100 --workers 4 --replicates 5 --seed 7 --seed-step 10 --open-viewer
```

Будут использованы seed `7, 17, 27, 37, 47`. Повторы идут последовательно,
потому что каждый является отдельной эволюцией. Внутри повтора `--workers 4`
параллельно считает разных кандидатов.

## Что меняется между повторами

Каждый seed создает заново:

- начальные веса всей популяции;
- последовательность мутаций;
- training-комнаты;
- validation-комнаты;
- holdout-комнаты.

Наборы не пересекаются. Поэтому пять строк не являются пятью просмотрами
одного победителя, а представляют пять независимых попыток найти навык.

## Как читать общий отчет

Сначала открой `results/compare_generalization/<run-id>/report.md`. Этап имеет
четыре заранее заданных условия:

- средний holdout не ниже `80%`;
- не менее четырех из пяти запусков имеют holdout не ниже `70%`;
- средний разрыв vertical/horizontal не больше `15` процентных пунктов;
- средний `stuck rate` не больше `10%`.

Среднее показывает общий уровень, а диапазон и стандартное отклонение
показывают надежность поиска. Среднее `82%` при результатах от `50%` до `100%`
хуже, чем пять результатов около `82%`.

## Фактический результат нашего этапа

Проведенный пятиseed-запуск получил:

```text
mean holdout = 85.94%
запуски >= 70% = 5/5
вердикт = PASS
```

Это не доказывает навигацию во всех возможных мирах. Оно означает, что при
зафиксированном протоколе поиск воспроизводимо решает новые комнаты лучше
заданного инженерного порога.

## Что смотреть в viewer

Live viewer сохраняет одну вкладку и переключает ее на текущий seed. В конце
`comparison-viewer.html` показывает до четырех лучших независимых запусков.
Эта общая сцена предназначена для объяснения различий в поведении. Рейтинг
все равно строится по всему holdout, а не по показанной траектории.

Для исследования неудач открой `runs/seed-*/viewer.html` и включи `Failure`.
Сравни, повторяется ли одна ошибка у разных seed. Повторяющаяся ошибка чаще
указывает на ограничение задачи или fitness, единичная может быть особенностью
пути эволюции.

## Файлы

- `comparison.csv` содержит итог каждого seed;
- `categories.csv` разбивает holdout на восемь типов комнат;
- `report.md` агрегирует критерии;
- `comparison-viewer.html` сравнивает победителей;
- `runs/seed-*/` хранит полный результат каждого повтора.

## Чему учит этот шаг

«Лучший найденный мозг» и «надежный способ обучения» являются разными
результатами. После подтверждения повторяемости можно задавать причинный
вопрос: [нужны ли wall-сенсоры](wall_sensor_ablation.md)?
