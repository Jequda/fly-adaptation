# Шаг 6. Нужны ли датчики стены

В viewer видно, что `wall left/front/right` меняются около препятствия. Но
совпадение во времени еще не доказывает, что мозг использует эти сигналы.
Причинный вопрос проверяется ablation: выбранная информация выключается, а
остальные условия сохраняются.

## Два эксперимента в одной команде

Для каждого seed запускаются:

```text
full              обучение со всеми 9 входами
no-wall-sensors   новое обучение, где три wall-входа всегда равны нулю
full-knockout     готовый full-мозг, но wall-входы выключены только на тесте
```

У всех сетей остается форма `9 -> hidden -> 3`. Мы обнуляем значения, а не
удаляем входы, чтобы число весов и размер архитектуры не стали побочной
причиной различия.

## 1. Коротко проверь механику

```powershell
uv run python -m experiments.compare_wall_sensors --generations 5 --population 16 --episodes 8 --validation-episodes 8 --holdout-episodes 16 --max-steps 80 --workers 4 --replicates 1 --effect-threshold 0.10 --open-viewer
```

В pair viewer сравни одну и ту же комнату. У `no-wall-sensors` и knockout три
полосы стены должны оставаться на нуле. Короткий запуск не предназначен для
вывода об их полезности.

## 2. Полный запуск

```powershell
uv run python -m experiments.compare_wall_sensors --generations 40 --population 80 --episodes 24 --validation-episodes 24 --holdout-episodes 64 --max-steps 100 --workers 4 --replicates 5 --seed 7 --seed-step 10 --effect-threshold 0.10 --open-viewer
```

Внутри каждой пары совпадают начальная случайность и все комнаты. Поэтому
разность условий меньше зависит от того, кому случайно достались простые
двери.

## Retraining и knockout отвечают на разные вопросы

Retraining сравнивает `full` с заново обученным `no-wall-sensors`:

```text
Может ли эволюция найти другую стратегию без этих датчиков?
```

Test-time knockout берет те же веса full-победителя:

```text
Использует ли конкретный найденный мозг эти датчики прямо сейчас?
```

Обе delta считаются как `full holdout - ablated holdout`. Порог практического
эффекта заранее установлен в `10` процентных пунктов.

## Как не сделать ложный вывод

Если full сам получил низкий результат, его падение после ablation ничего не
говорит. Поэтому отчет сначала повторно проверяет baseline: общий holdout,
долю успешных seed, баланс ориентаций и застревания. Причинный вывод разрешен
только при рабочем baseline.

## Как читать сочетание эффектов

| Retraining | Knockout | Значение |
| --- | --- | --- |
| большой | большой | датчики помогают найти навык, и победитель ими пользуется |
| маленький | большой | победитель зависит от них, но возможно выучить альтернативу |
| большой | маленький | датчики помогают поиску, хотя победитель устойчив к выключению |
| маленький | маленький | эта версия задачи почти не требует сигналов стены |

## Наш результат

Пятиseed-протокол дал:

```text
retraining effect = +34.69 процентного пункта
knockout effect   = +83.75 процентного пункта
```

Следовательно, wall-сенсоры не просто коррелировали с поворотом. Они заметно
помогали обучению, а готовые full-мозги причинно зависели от них.
