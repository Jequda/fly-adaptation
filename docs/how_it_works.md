# Как работает Fly Adaptation

Эта глава нужна перед экспериментами. Здесь нет требования уже знать
нейросети: мы разберем систему от одного шага агента до целого поколения.

## 1. Самая короткая модель проекта

В каждом эпизоде повторяется один цикл:

```text
мир -> сенсоры -> мозг -> моторы -> новое состояние мира
                         |
                         -> score
```

Мозг не получает команду «поверни к еде». Он получает несколько чисел от
сенсоров и выдает три числа для движения. После эпизода среда сообщает, было ли
поведение полезным. Эволюция сохраняет удачные мозги и немного изменяет их
копии.

## 2. Запусти базовый опыт

Из корня проекта в PowerShell:

```powershell
uv run python -m experiments.find_food --generations 15 --population 30 --episodes 5 --workers 4 --open-viewer
```

Для совсем короткой проверки используй:

```powershell
uv run python -m experiments.find_food --generations 3 --population 12 --episodes 2 --workers 2 --open-viewer
```

Короткий запуск показывает механику, но по нему нельзя делать научный вывод.

## 3. Что происходит при запуске

1. Создаются `population` случайных мозгов.
2. Каждый мозг проходит одинаковый набор из `episodes` сцен.
3. Для него вычисляется fitness.
4. Лучшие мозги сохраняются как родители.
5. Их копии получают небольшие случайные мутации.
6. Новая популяция становится следующим поколением.
7. После последнего поколения сохраняются отчет, мозг и viewer.

Одинаковые сцены внутри поколения важны. Если один кандидат получил простую
цель, а другой сложную, сравнение их fitness было бы нечестным.

## 4. Мир и один эпизод

Базовый мир является квадратом `10 x 10`. В начале случайно выбираются:

- положение агента;
- направление его головы;
- положение еды.

Один эпизод длится не больше `max_steps`. Он завершается раньше, если агент
касается еды.

На каждом шаге мир сначала вычисляет наблюдение, затем мозг отвечает, после
чего меняются направление и положение тела. Мозг не видит Python-объекты,
карту или готовые координаты цели. Он видит только свой числовой вектор.

## 5. Сенсоры базового мира

В `find_food` на вход мозга поступают шесть чисел:

```text
sin angle, cos angle, distance, agent x, agent y, bias
```

`sin angle` и `cos angle` вместе описывают направление на еду относительно
головы. Два числа нужны, потому что угол цикличен: направления около `-pi` и
`+pi` почти одинаковы, хотя обычные числа выглядят далекими.

`distance` сообщает нормированное расстояние. `agent x/y` задают абсолютное
положение. `bias` всегда равен `1` и позволяет нейронам иметь устойчивое
смещение даже при нулевых остальных входах.

В следующих опытах набор сенсоров меняется. Это часть исследования: мы
проверяем, какая информация действительно нужна.

## 6. Что находится внутри мозга

Мозг состоит из трех частей:

```text
сенсоры -> hidden-нейроны -> моторы
                ^
                |
          прошлый hidden-state
```

У каждого hidden-нейрона есть входящие веса, смещение и связи от hidden-state
предыдущего шага. Упрощенно его новое значение выглядит так:

```text
new_hidden = tanh(сенсоры * веса + old_hidden * recurrent_веса + bias)
```

`tanh` ограничивает значение диапазоном от `-1` до `+1`. Затем значения
hidden-нейронов преобразуются в три моторных выхода.

### Что означают цветные клетки в viewer

Каждая клетка в блоке `Selected brain` является одним hidden-нейроном:

- холодный цвет означает отрицательную активацию;
- светлый цвет означает значение около нуля;
- теплый цвет означает положительную активацию;
- насыщенность показывает модуль значения.

Положение клетки в сетке не означает анатомическую область. Нейрон номер 7 не
является заранее «нейроном еды» или «нейроном памяти». Его роль возникает из
набора весов и может отличаться у другого победителя.

Цвет также не показывает важность нейрона. Чтобы доказать причинную роль,
нужно выключить нейрон или сенсор и снова измерить поведение. Именно поэтому в
маршруте есть ablation-эксперименты.

## 7. Моторные выходы

Мозг выдает три числа:

```text
turn left, turn right, move forward
```

Разность правого и левого сигналов меняет направление. Положительная часть
`move forward` задает скорость вперед. У агента нет отдельной кнопки «съесть»:
еда считается съеденной при касании.

## 8. Score и fitness

В базовом мире score складывается из трех частей:

```text
приблизился к цели  -> небольшая награда
потратил шаг        -> небольшой штраф
коснулся еды        -> большая награда
```

Промежуточная награда за приближение нужна как подсказка поиску. Без нее
случайный мозг почти никогда не коснулся бы маленькой цели, и большинство
кандидатов получало бы одинаковый нулевой сигнал.

`score` относится к одному эпизоду. `fitness` объединяет несколько эпизодов и
используется для отбора родителей. В простом опыте fitness является средним
score. В опыте выбора цели формула дополнительно защищает слабые категории,
чтобы стратегия «всегда иди к A» не выглядела хорошей.

Важно: fitness не обучает веса градиентом и не объясняет готовое действие. Он
только определяет, чьи потомки попадут в следующее поколение.

## 9. Отбор и мутация

После оценки популяция сортируется по fitness. Верхняя доля, заданная
`elite_fraction`, становится родителями. Часть следующего поколения является
их точными копиями, остальные являются мутировавшими копиями.

Мутация может:

- немного изменить отдельные веса;
- добавить hidden-нейрон;
- удалить hidden-нейрон в разрешенных пределах.

Поэтому `avg_hidden` иногда меняется. Большее число нейронов не обязательно
лучше: оно лишь дает больше возможных связей и одновременно расширяет
пространство поиска.

## 10. Что такое поколение

Поколение не является одним движением агента. Это полный экзамен всей
популяции:

```text
1 поколение
  -> 30 мозгов
      -> по 5 отдельных эпизодов
  -> сравнение fitness
  -> родители и потомки
```

Поколения идут последовательно, потому что для создания следующего нужны
победители текущего. Параметр `--workers 4` параллельно оценивает разные мозги
внутри поколения. Поэтому несколько процессов в viewer являются кандидатами,
а не четырьмя независимо развивающимися поколениями.

## 11. Training, validation и holdout

В первых простых опытах достаточно training. В более серьезных опытах данные
разделены:

```text
training   -> влияет на родителей и мутации
validation -> выбирает лучший checkpoint среди поколений
holdout    -> один раз проверяет уже выбранный checkpoint
```

Checkpoint является сохраненным состоянием мозга из конкретного поколения.
Последнее поколение не обязано быть лучшим: эволюция может временно улучшить
одну сцену и ухудшить другую. Поэтому мы сохраняем поколение с лучшим
validation.

Holdout не участвует ни в отборе, ни в выборе checkpoint. Это новые сцены,
которые отвечают на вопрос: выучено общее правило или запомнены примеры?

## 12. Seed и воспроизводимость

`--seed 7` фиксирует последовательность псевдослучайных чисел. С тем же кодом,
параметрами и seed запуск можно повторить.

Один seed отвечает на вопрос «может ли поиск найти решение?». Несколько seed
отвечают на более сильный вопрос «насколько регулярно он его находит?». Поэтому
после каждого одиночного опыта маршрут переходит к команде `compare_*`.

## 13. Как читать live viewer

Viewer открывается сразу с `--open-viewer`. Во время обучения он показывает
выборку кандидатов текущего поколения и диагностические сцены лидера.

Смотри в таком порядке:

1. Заголовок плитки: поколение, кандидат, условие и seed.
2. Поле: траектория тела, цель и препятствия.
3. Sensors: какую информацию мозг получает сейчас.
4. Motors: какое действие он выдает.
5. Hidden: как меняется внутреннее состояние.
6. Графики: улучшается ли не только лучший мозг, но и популяция.

Live viewer получает уже рассчитанные трассы и не управляет обучением. После
завершения создается самостоятельный `viewer.html`, который можно открыть без
Python-сервера.

Если браузер не открылся автоматически, терминал печатает строку
`Live visualization: http://...`. Открой этот адрес вручную. Для готового
запуска можно открыть `viewer.html` из каталога результата.

## 14. Как читать терминал

Пример строки:

```text
12,131.200,72.400,0.67,24.10
```

- `12` - индекс поколения; отсчет начинается с нуля;
- `best_score` - fitness лидера текущего поколения;
- `avg_score` - средний fitness всех мозгов;
- `best_eat_rate` - доля решенных training-сцен у лидера;
- `avg_hidden` - среднее число hidden-нейронов.

Высокий `best_score` при низком `avg_score` означает, что удачная мутация уже
появилась, но еще не распространилась. Рост только training без validation
может означать переобучение.

## 15. Как читать каталог результата

После запуска открой `results/<experiment>/<run-id>/`:

- сначала `report.md`, там вопрос, критерии и итог;
- затем `config.json`, там точные параметры;
- потом `metrics.csv` и диагностические CSV;
- после этого `viewer.html`, особенно фильтр неудачных эпизодов;
- JSON мозга нужен для повторной оценки и следующих экспериментов.

Правильный порядок именно такой: сначала метрика по всем сценам, потом
объясняющая траектория. Один красивый replay может быть исключением.

## 16. Небольшая самостоятельная работа

Запусти базовый опыт дважды:

```powershell
uv run python -m experiments.find_food --generations 10 --population 20 --episodes 3 --seed 7 --workers 4
uv run python -m experiments.find_food --generations 10 --population 20 --episodes 3 --seed 17 --workers 4
```

До просмотра результата запиши три предположения:

1. В каком поколении впервые появится успешный агент?
2. Будет ли расти средний fitness вслед за лучшим?
3. Получат ли два seed одинаковый итог?

После запуска сравни `report.md` и `metrics.csv`. Здесь начинается нормальная
экспериментальная работа: гипотеза, измерение, объяснение различий.
