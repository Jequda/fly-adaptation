# Fly Adaptation

Учебная лаборатория, в которой маленькие нейросети эволюционируют в
виртуальном мире. Проект построен как последовательность вопросов:

```text
может ли агент двигаться к цели?
может ли он помнить исчезнувшую информацию?
может ли перенести навык в новую комнату?
какие сенсоры действительно нужны?
может ли запомнить правило выбора?
```

Мы не пытаемся сразу собрать "сознание мухи". Сначала учимся ставить честные
эксперименты на маленькой модели, а затем переносим эти навыки на модель
Drosophila.

## С чего начать

Открой [docs/how_it_works.md](docs/how_it_works.md). Это главный учебник по
проекту. Он объясняет мир, мозг, поколения, fitness, validation, holdout и
viewer без предположения, что ты уже знаешь машинное обучение.

Затем проходи эксперименты по порядку из раздела "Учебный маршрут" ниже.

## Установка и проверка

Проект использует Python 3.12 и `uv`. В PowerShell из корня проекта:

```powershell
uv sync
uv run python -m unittest discover -s tests
```

Активировать `.venv` вручную не обязательно. Команда `uv run` сама выберет
окружение проекта.

## Первый запуск за несколько минут

```powershell
uv run python -m experiments.find_food --generations 15 --population 30 --episodes 5 --workers 4 --open-viewer
```

Что произойдет:

1. Программа создаст популяцию случайных мозгов.
2. Каждый мозг пройдет пять эпизодов.
3. Лучшие дадут потомков с небольшими мутациями.
4. Браузер сразу откроет живой viewer.
5. После завершения результаты сохранятся в `results/find_food/<run-id>/`.

В viewer выбери плитку агента и наблюдай:

- положение и направление тела;
- сенсоры справа;
- три моторных выхода;
- цветные клетки hidden-state;
- score и успешность по поколениям.

Viewer проигрывает уже вычисленную траекторию. Он не замедляет эволюцию.

## Как устроен честный эксперимент

В сложных опытах сцены разделены на три набора:

```text
training   -> определяет fitness, родителей и мутации
validation -> выбирает поколение, которое мы сохраним
holdout    -> финальный экзамен после выбора
```

Holdout нельзя использовать для подбора параметров внутри запуска. Иначе это
уже дополнительный training, только под другим именем.

Один успешный seed показывает, что решение существует. Несколько независимых
seed показывают, насколько надежно эволюция его находит.

## Что означают основные параметры

- `--population 80` - число мозгов в поколении.
- `--generations 40` - число циклов отбора и мутаций.
- `--episodes 32` - число training-сцен для каждого мозга.
- `--validation-episodes 32` - сцены для выбора checkpoint; сложный опыт
  выбора цели использует `64`.
- `--holdout-episodes 64` - новые сцены финального экзамена.
- `--hidden 24` - начальное число hidden-нейронов.
- `--workers 4` - сколько мозгов считать параллельно.
- `--seed 7` - воспроизводимая случайность.
- `--open-viewer` - сразу открыть живую визуализацию.

Поколения идут последовательно: следующее поколение нельзя создать, пока не
выбраны родители текущего. Параллельно считаются мозги внутри поколения.

## Как читать строки терминала

Пример:

```text
generation,best_score,avg_score,best_eat_rate,avg_hidden
12,131.2,72.4,0.67,24.1
```

- `best_score` - лучший fitness текущего поколения.
- `avg_score` - средний fitness популяции.
- `best_eat_rate` - доля training-эпизодов, решенных лидером.
- `avg_hidden` - среднее число hidden-нейронов.

Высокий лучший результат при низком среднем означает, что решение уже
появилось, но еще не распространилось по популяции.

## Где искать результаты

Каждый запуск создает отдельный каталог с датой и временем:

```text
results/<experiment>/<run-id>/
```

Обычно внутри есть:

- `config.json` - точные параметры и seed;
- `metrics.csv` - история поколений;
- `best_validation_genome.json` - выбранный мозг;
- `evaluation.csv` - результаты отдельных эпизодов;
- `report.md` - вывод по метрикам;
- `viewer.html` - самостоятельная визуализация holdout;
- `validation-viewer.html` - сцены выбранного checkpoint.

Сначала читай `report.md`, затем смотри неудачные эпизоды в viewer. Красивый
одиночный replay не заменяет статистику по всему holdout.

## Полезные правила обучения

1. Меняй за раз одну идею.
2. До запуска запиши, какой результат подтвердит гипотезу.
3. Не выбирай победителя по holdout.
4. Проверяй несколько seed.
5. Смотри не только среднее, но и худшую категорию.
6. Используй ablation: выключи информацию и измерь изменение.
7. Храни неудачные результаты. Они показывают, где эксперимент был нечестным
   или поиск был нестабильным.

## Текущий рубеж

Мы прошли путь от движения к цели до памяти правила выбора. Первый вариант
последнего опыта дал высокий одиночный результат, но провалился на пяти seed.
После этого протокол был усилен: одинаковая геометрия теперь проверяется парой
`Cue A` и `Cue B`, fitness учитывает восемь комбинаций команды и квадранта, а
pair alignment поощряет даже небольшой правильный разъезд траекторий до первого
касания цели. Pair contrast отдельно отмечает уже завершенные разные выборы.
Между поколениями также меняются 16 сбалансированных training-банков. Так угол
цели не может заменить память команды, а слабое направление не скрывается
средним.

Полный пятиseed-повтор прошел все заранее записанные критерии: recurrent
holdout `94.06%`, stateless `50.00%`, преимущество памяти `44.06` пункта и
падение при test-time knockout `62.81` пункта. Все пять recurrent-запусков
превысили `70%`, а худшая объединенная категория получила `90%`.

Самым слабым остался seed `37`: общий holdout `81.25%`, а две его отдельные
категории получили по `50%`. Это не отменяет PASS пятиseed-протокола, но
остается честной границей надежности маленькой модели.

Следующий этап проекта - подключение данных Drosophila и готовой LIF-модели.
